# 第零轮实施与验收记录

日期：2026-09-06。结论：第零轮目标已完成；第一轮场景及观测改动尚未开始。

## 1. 实施边界

保持训练环境源码不变：16 维输入、世界坐标相对速度、中心距离、线性安全奖励、进展权重 10、随机半径和竖直运动均保留。PPO 学习率仍为 `1e-4`，网络仍为两层 64 单元。未删除或覆盖旧根目录模型和日志。

修复训练/评估流程，而不是优化策略本身：

- 训练结束总是评估最后一次 PPO 更新后的参数。环境步数相同但参数更新次数不同的记录合法，新增 `policy_updates` 字段用于区分。
- 无 Git 提交可用时，也保存关键源码哈希和源码快照，避免仅凭手写 schema 字符串推断代码一致。
- 认证模型必须具有匹配的运行 ID、模型路径、模型哈希、源码契约及已完成状态；训练续跑还核验 seed、PPO 配置和验证集。
- 同一运行仅能从自己的最新认证 final 模型继续；从 best 分支训练须使用新 run ID。未认证检查点和旧模型拒绝安全续训，不推测其来源。
- 默认模型路径或显式模型路径若归属于有元数据的运行，也执行身份核验。显式评估旧模型仍允许，但结果明确标记训练身份未核实。
- 配对诊断冻结障碍时保持原场景速度归一化分母不变。该修复仅作用于诊断，不改变训练观测。

安全续训不等于逐位重放：恢复模型/优化器和累计步数，但不恢复中断时的所有随机数状态、未完成回合及完整环境状态。源码哈希检查采取保守拒绝策略，连相关脚本编辑也会触发不兼容；后续修改后不能直接把旧模型视为同契约模型。

## 3. 开发诊断结果

所有变体使用同一个最佳模型和验证集派生场景，每种 30 回合。

| 变体 | 成功数 | 说明 |
|---|---:|---|
| 原场景 | 23 | 29 个轨迹被分类为上绕，1 个居中 |
| 上下镜像 | 14 | 仍有 27 个上绕，仅 1 个场景符合预期镜像侧别 |
| 冻结动态障碍 | 20 | 保持原场景速度归一化分母 |
| 反转动态速度 | 24 | 保持其他几何参数 |
| 远置动态障碍 | 24 | 零半径远处代理，不是真正无障碍 |

这些结果固化了当前方向偏好与运动变化敏感性的诊断起点，不能单独证明合理动态避让。尤其是碰撞终止导致的轨迹长度变化不能直接视为策略主动避让；远置变体也同时改变几何，不作严格单因素运动因果证据。

## 6. 复现方式

重新训练使用新的运行 ID，避免覆盖已冻结基线：

```powershell
.\.venv\Scripts\python.exe scripts\train.py --timesteps 200000 --seed 1 --run-id round0-reproduction-seed1 --device cpu
.\.venv\Scripts\python.exe scripts\freeze_round_zero.py --run-dir runs\round0-reproduction-seed1
```

冻结脚本只评估验证集并派生开发诊断，不使用最终独立测试集；若 `round_zero` 已存在则拒绝覆盖。不同依赖或硬件下重新训练不承诺逐位相同，本轮验证的是同一模型在当前环境中的确定性评估可复现性。
